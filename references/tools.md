# 工具指南

本目录自带的程序无需阅读源码；命令中的 `<skill>` 应替换为本 Skill 的安装目录。本文只说明使用时机与最常用的命令；全部选项、动作写法和输出文件见各自的 `--help`，书写错误时报错信息会给出可直接照抄的正确写法。

宿主自有浏览器工具时，查看页面、走查流程照常使用。需要交付证据时优先使用这里的截图工具：它启动一个独立的临时浏览器，不会触碰用户自己浏览器中的数据。本机缺少 Node 22，或者没有 Chrome、Chromium、Edge 时，退回宿主工具，交付同样的证据。任务或项目已经指定了截图工具时，照用该工具。

## 截图和录屏

### 截取时机与截取范围

截图分两种用途，不应混同：

- **查看效果**：改完一批之后，希望查看呈现效果。只截当前这一屏，用一条命令完成。应把一批改动攒在一起改完再截，而不是每改一处截一次；页面没有变化，就不重复截图。
- **取证**：使用 `--evidence` 一次取齐状态图、并排图、遮字图、2 倍图和录屏。仅在两个时机执行：送评审之前、交付之前。方向首屏那一轮每个方向只截一张，不取证。

每一轮评审只重新采集本轮改动影响到的证据。未做改动的状态和动效，沿用上一轮的文件，交接时注明哪些属于沿用；无法确定是否被影响时（例如改动了共享样式），就重新采集该项。

### 常用命令

```text
node <skill>/scripts/shoot.mjs <页面地址、HTML 文件或候选目录> [选项]
```

| 需求 | 附加参数 |
| --- | --- |
| 查看桌面端效果 | `--size desktop`；不写时默认为手机 390x844；只看整体版式可加 `--thumb`（以 0.5 倍速截图） |
| 一次截完多个候选并生成并排图 | 直接传入候选目录（如 `explore`）或多个 HTML 文件，在同一次浏览器会话中截完并自动生成 `sheet.png` |
| 只看改动过的局部组件或区域 | `--selector ".card"`，自动滚入视口并只截该元素的区域 |
| 执行若干步操作后再截 | `--steps "click .open; wait 300"` |
| 送评审或交付前取证 | `--evidence --states idle,done --steps "send: click .send"`（汇总末行直接打印评审手册与证据目录路径） |
| 落地页录制一段从头滚到底 | `--record --steps "scroll 600; scroll 600; scroll 600"`，按页面长度增加步数 |
| 截图还原：与参考图比对 | `--compare 参考.png --size <参考的逻辑尺寸>` |
| 向用户指出问题：在元素上画框并标注编号 | `--mark "1=.page-head .btn; 2=.toggle-row" --full` |
| 看清一段过渡过程 | 录屏时加 `--frames 8`，另外输出逐帧标注时间的序列图 |
| 将几张图拼成一张对比图，无需打开页面 | `--stitch a.png --label 修改前 --stitch b.png --label 修改后` |

状态通过地址参数进入，因此页面必须能够通过 `?state=<名字>` 直接打开每一个状态。其余选项、选择器和动作的写法、输出文件以及 `report.json` 的结构：运行 `node <skill>/scripts/shoot.mjs --help` 查看。无法确定写法时先加 `--dry-run` 校验，不会启动浏览器。超时会放宽时限自动重跑一次，仍失败时按报错中的命令重跑。

### 检索和下载真实素材

在项目工作目录中运行，后续命令也应在同一目录执行，搜索结果的编号才能衔接：

```text
node <skill>/scripts/curate-media.mjs search "<关键词>" --kind texture --limit 6 --sheet --dir candidates
node <skill>/scripts/curate-media.mjs search "<一组词> | <另一组词>" --sheet --dir candidates
node <skill>/scripts/curate-media.mjs preview V1,T2 --sheet --dir candidates
node <skill>/scripts/curate-media.mjs fetch C1,T2 --dir assets --sheet
node <skill>/scripts/curate-media.mjs fetch V3 --dir <不上线的参考图目录>
node <skill>/scripts/curate-media.mjs fetch T2 --maps all --resolution 1k --dir assets
```

`--kind` 支持 `all|texture|design|photo|blueprint|map|plate|science|video`。信源涵盖材质库、欧美与日本的博物馆和图书馆馆藏、NASA，各类别对应哪些信源见 `--help`。`all` 会交错取自各信源；使用 `|` 可一次搜索多组关键词。关键词多采用英文，东亚题材可直接使用中文或日文，简体中文检索无结果时改用繁体或日文写法。

结果存入 `.curate-cache.json`，编号跨次搜索保留。每项的 `use` 字段说明用途：`page` 可放入页面（CC BY/BY-SA 需署名），`check` 需先查看来源页，`reference` 不能放入页面；`--use page` 只保留第一种。

`search --sheet` 与 `preview` 输出带编号、用途和原图尺寸的联系表 PNG，应直接读取这张图进行挑选，不要只看标题；同时为每一项计算 `look`（四边色彩、是否为浅色纸底、哪些区域干净可叠加文字等），并输出 HTML 联系表。`fetch --sheet` 输出本地联系表并校验真实宽高与完整解码；视频自动截取首帧作为 poster。

贴图默认下载 1k 的 Diffuse，`--maps all` 会拉取 Diffuse、Roughness、OpenGL Normal 的 JPG 并校验大小与 MD5；使用规范与许可见 [素材指南](media.md#真实贴图与科学工程素材)。下载文件及 poster 会自动写入同目录的 `SOURCES.md`，亦兼容 `fetch "<URL>" --out assets/<文件名> --note "来源说明"` 的写法。全部选项见 `node <skill>/scripts/curate-media.mjs --help`。

### 查看结果

交付评审前先自行查看：默认状态是否已经完成加载，遮字版有没有把图形一并遮盖。证据存在问题应先重新截图，再交付评审。汇总中提示录屏和截图不一致时，静止的终态以截图为准，再单独重录那一段核对过渡过程。画面为空白的 WebGL 截图不能作为证据。

每张截图还会检查一组能够从页面样式中直接判定的问题，命令输出中以"默认做法提示"列出：

- **必须修正的可读性问题**：文字对比度不达标、正文小于 13px、多行正文行高过紧、首屏中停留在透明状态的内容。
- **应当改掉或写出理由**：有色底上的灰色文字、正文行宽过大，以及模型默认做法：标题上方的眉标与编号标签、彩色单侧边线、渐变文字、卡片内嵌套卡片、以表情符号充当图标、中文界面中的英文大写标签、标题与上文间距小于与下文间距。决定保留的项，须在交付说明中写明它如何服务于设计方向。

该检查会产生误报，例如真实的步骤编号、确实需要的标签；属于误报的在交付说明中写明一句。它只识别写法，无法判断优劣：提示清零之后，仍须自行查看截图。检查报出接口 401、404 这类与画面无关的错误时，在交付说明中记录一行，不得为了让检查通过而修改登录、接口这类业务代码。

## 编写可操作的小样

方向探索阶段的首屏不做交互，用不到本节；选定方向后制作完整页面时再行使用。存量项目照用项目自身的技术栈。

一个组件或一个页面只写一个文件，通过地址参数切换状态，不要为每个状态复制一份。颜色、字号、间距、圆角先确定为十来个 CSS 变量，后续一律引用变量，不引入需要构建的工具。表单、切换、展开这类状态使用 Alpine.js 写在 HTML 属性上：先将 `<skill>/assets/vendor/alpine.min.js` 复制到任务目录的 `vendor/` 再行引用，状态集中在一个 `x-data` 中，初始状态读取地址参数。手势跟手、物理模拟、Canvas 和 WebGL 绘制放入单独的 JS 模块，每帧更新的数据不放入 Alpine 的状态。
