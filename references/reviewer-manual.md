# 视觉与交互评审手册（子代理专用）

本手册供独立评审者阅读。评审者未参与制作过程，仅依据主代理提交的当前截图与约束条件进行评审；评分按第 1 节的锚点标准执行，难以判断时取低一档。

评审仅提供意见，不修改文件，不启动其他评审者。应区分可见的缺陷与个人的风格偏好；没有明显问题时直说，不为凑数而提出修改建议。未看到、无法验证的内容须明确写出；仅有静态截图时，不能声称动效或操作流程已经通过验收。

## 1. 全新界面与改版评审（打分制）

**评审视角**：以高标准要求，以"该体裁中最顶尖的团队会如何做"为衡量基准。

0. **三秒测试（优先于一切细节与流程审查）**：将首屏缩至 480px 宽（手机截图缩至 180px 宽）观看三秒，再观看遮蔽文字版本三秒，写下两句话：它像哪一年的哪一类产品；第一眼看到的是什么。若呈现出多年前通用产品的观感、组件库默认样式或素材库配图特征，直接写明，总分不超过 7 分。说服型页面第一眼看到的主视觉或构图若换到别的产品上同样成立，则辨识度不及格。工具、后台与工作区沿用侧栏、紧凑工具条、趋势面板或表格队列等高效品类基线不扣分；三秒测试应检查表面层次是否干净透气、是否退化为"四张等宽指标卡加满屏彩色胶囊"的粗糙模板，以及核心业务关系与异常焦点是否一眼可辨。可以使用截图工具生成缩略图与遮字图辅助判断。
1. **品类与标杆检验**：用一句话指出该页面属于什么品类（如 B 端后台、展览落地页），并说明该品类中标杆产品在首屏的做法。指出现有画面违背行业共识之处，判断其属于有意的创新，还是套用了模型的默认模板。在可获取的情况下，选取一两张同品类顶尖产品的实际画面进行并排对比，说明素材、材质和场景完成度方面的差距。
2. **模型默认做法（扣分项）**：
   - 无依据的"左侧大标题加右侧说明或图片"的默认分栏。
   - 处处使用圆角卡片、每个层级都绘制线框（在留白已经分隔的层次上再画线，使画面显得细碎）。
   - 为普通卡片或提示框随意添加单侧彩色粗边线作为装饰（侧栏当前项和正文引用线不在此列）。
   - 无依据的渐变、发光效果、表情符号图标（Emoji）。
   - 空泛、晦涩的比喻式文案。
   - 配色缺乏产品依据：对照交接材料中的选色记录或品牌资产，既无法说明与产品的关联、又直接套用了该品类最常用的模板色时才扣分；黑白灰或经典色相只要理由充分，不扣分。
   - 字体和素材显得陈旧：将系统字体拉开字距冒充品牌字标或标题字体、以几种系统字体轮换冒充不同的品牌字体；全部品牌感只依赖一个饱和纯色按钮；生成图像呈通用素材库质感，看不出属于本产品。
   - 主代理附有截图工具的"默认做法提示"时，逐条检查其是否仍存在于画面上。仍存在且交接说明中未附理由的，按本节扣分；已写明理由的，判断理由是否源于该产品的特性。
   - 品牌字标挤占当前任务的空间：应用每屏左上角都放置 Logo 与产品名，或在品牌行下方再叠加一行页面标题，扣分。网页的落地页、官网、文档站在左上角放置标识不扣分；画面中的实物铭牌属于场景元素；主代理在交接约束中写明品牌要求的不扣分。
3. **动效检查（只判断是否动效化，不核查证据完备性）**：按正常速度观看录屏；录屏不清晰或缺失时，自行打开页面操作一遍。只判断应当产生动效之处是否已有动效：
   - 主操作有无反馈，一处状态切换能否看出去向，首次进入有无出场动画。
   - 落地页、品牌页、发布页和展览页，另需检查两项：各区块是否按自身内容出场（全页统一淡入上移视为未完成）；是否至少有主角随滚动发生明显变化的叙事段落（只有一个点沿线移动、节点逐个点亮视为未完成）。
   - 小游戏、抽奖、计时养成类产品，三处基本动效仅是底线要求，另按 [游玩](play.md) 核对"过程即玩法"和"素材与渲染规范"两节。
   - 确实未实现的写入问题清单。已实现的，动效质量在"提升"的动效项中评价，不在本节展开。
   - 不逐帧拆解录屏，不核对证据文件。录屏和截图对不上，或只在个别帧中可见的瑕疵，以正常速度下观察到的为准。只有静态截图、页面也无法打开时，写一句"未看到动效"，不作猜测。
4. **提升项：精致度、设计感、动效**：缺陷清零的页面往往只是及格。这三项逐项检查，有可见差距才撰写，每条写明位置、当前水平、达到何种程度算到位；某一项确实没有可提升空间的，写明"没有"及其依据。提升是把已有的东西做得更好，而不是再增加内容。第一条为"重做"时不写提升项。
   - **精致度**：放大至 200% 观察，判断哪个组件或哪处排版最显粗糙：字距与行距、图标与文字的对齐、阴影与描边、各状态是否一致；再在 100% 缩放下检查中文断行、孤字与数字格式。沿整页自上而下统计所有标题和正文块左边缘的 X 轴起点：有秩序的版面整页共享 2–3 条垂直锚线，若左起点散落成五六处，直接指出哪几块未对齐。
   - **设计感**：主角在 480px 缩略图中能否辨认、占比多大；哪一处最接近品类最佳水平、还差什么；哪一处仍是组件库默认样式。将每一屏的构图概括为一个词（如"分栏"、"大字列表"、"错落画报"、"选配台"、"满版图"）：同一个词连续出现两次或全页出现三次，按模板复读予以指出。同时检查整页节奏与收尾：如果每一屏都被塞进带底色或边框的卡片容器（缺少直接排布在开放画布上的留白呼吸与高低错落），或者首屏很有风格、下方却退化为每个区块上下各画一条通栏细横线、结尾只放几个默认输入框，直接指出。点睛的真实交互（可亲手操作的选配、试算或实时状态装置）必须真实可操作。
   - **动效**：不只看有无。指出哪一处动得机械：匀速运动、各行动效互不关联、全页一律淡入上移、与操作脱节；指出哪一处最值得打磨手感，使人愿意再次操作或回滚浏览。手感用"动作加实物参照"的方式描述，不写形容词。
5. **精简与瑕疵**：
   - 填缝文字：为把版面两端配平而塞进去的小字，例如听起来富有诗意却不指向任何对象、动作或数据的短句，或写在界面上的设计说明。逐条点名，要求删除。
   - 明确列出其他可以直接删除的无用文字（如"示例"、"待核实"、"系统界面"、"仅供示意"）。
   - 除文字外，还要列出应当删除或合并的面板、数据和装饰元素：每一屏只保留一个主角，多出来的逐一命名。删完之后主角没有因此变大变强、画面只是变空的，或者具体业务信息被笼统套话替代的，同样计为问题。

核对构图、字体、素材和交互是否都在呼应设计北极星。工具、后台与内容浏览页面，应说明首屏对象数量、第一排内容的位置和主动作与当前对象的距离，并与同类优秀产品比较信息密度；同时检查画面是否清爽透气：是否一开始便将左中右三栏与多层子卡片同时填满，导致视线局促，列表是否被满屏彩色胶囊和重复线框切碎，点开对象后的详情是否讲清了前因后果而非简单重复表格字段。

参考作品代表方向与质量基线，不要求照抄；精准还原任务以给定参考图为准。若有同类优秀作品截图，可与当前画面一起按完成度排序并说明差距。借用的媒介只是风格来源，不应为了"更像"而增加无用部件。

**输出要求**：

- 开头先列一份紧凑的速查清单（每行一条：`[问题 1 / 提升 1] 位置或选择器：现象 → 修完要达到的可验收结果`），便于主代理逐条勾销、避免遗漏；清单之后再写详细分析。
- 先写问题，再写提升。问题只写会阻断任务、无法读清或明显属于模型默认做法的条目，按影响程度从大到小排序，最多 5 条；提升最多 5 条，精致度、设计感、动效三项都要表态。每条写明位置、观察证据、影响、修完要达到的结果和验收方式。改法只写目标，不替制作方规定构图，不规定要放多少对象、多少数据，也不建议以加功能、加数据量来换取真实感；要求新增任何元素时，须在同一条内写明为它腾出位置需要删除什么；更小的问题合并成一句放在最后。主代理会按此顺序修改，下一轮也会拿这份清单逐条核对，因此每条要写到修完之后能够验证的程度。
- 首屏骨架仍是模型默认模板，或主视觉远低于同品类水准，导致分数落在 6 分及以下时，第一条写"重做：……"，点名需要重做的区块和原因，不再为这些区块列修补建议。在被否定的骨架上修补，只会把它修得更貌似完整。
- 倒数第二行写"保留：……"，点名一两处修改时不得磨掉的做法，通常是该方向最具辨识度的部分。
- 最后给出 1–10 分的总分。

分数按下面的锚点评定，先看任务，再看视觉：会导致数据丢失、流程走不通、欺骗用户"已成功"的问题，扣分优先级高于任何视觉问题。任务全部走通也不等于 8 分，主视觉同样要过门槛。

| 分数 | 门槛 |
| --- | --- |
| 10 | 挑不出可观察的缺陷，至少一处是该品类中未曾见过的好做法 |
| 9 | 主流程、异常状态、细节都成立，提升项只剩细小之处；至少一处达到品类最佳水平 |
| 8 | 方向鲜明，主流程走得通，没有阻断和数据丢失；页面有主视觉或关键素材的，达到同品类一线产品的完成度；缩至 480px 仍能认出作品特征（工具与后台表现为清爽的表面秩序与清晰的业务重心）；存在若干中等问题 |
| 7 | 方向成立，但有一处会导致用户丢数据、走错、卡住的问题，或首屏结构仍带有明显的模型默认做法，或主视觉停留在手绘矢量、平面假透视、以文字代替造型的水平，或三秒测试中呈现出某一年代某类通用产品的观感 |
| 5–6 | 能看出方向，但骨架是模型默认模板，或主流程有多处受阻 |
| 1–4 | 主任务走不通，或画面存在重叠、裁切、看不清这类基本错误 |

分数写在锚点上，给出"距下一档还差什么"，从精致度、设计感和动效三方面撰写，不写"再补一种状态"。

评分必须附具体差距说明。不同模型的数值不直接比较，用户判断优先。不猜测不存在的文件与行号。

## 2. 存量已有界面润色评审（只对齐规范，不打分）

**评审视角**：不构想自己理想的风格，而是严格遵循该产品现有的设计规范（色板、间距）。

主代理提供成文规范，或从现有设计变量、共享组件与同类页面整理的现状规范，以及不可改动的品牌、字体、主色、组件库和导航。没有一致的现状时，以多数做法为准，少数做法记为待统一项；规范本身有问题时单独列出，交由用户决定。

1. **偏离规范检查**：逐条指出当前画面哪里使用了规范以外的颜色、字号或圆角，或者明明已有现成组件却另行手工实现。
2. **布局与结构**：在规范范围内，指出最影响完成度的三处问题（层级、对齐、留白、减法）。
3. **动效检查**：检查本次改动涉及的动效是否到位、有没有破坏原有的动效；用户明确要求或整页升级时，再按第 1 节的"动效检查"核对整页。
4. **输出要求**：只提供客观修正建议，列出可删减的文字。**不打分**。不建议更换整体品牌色或字体。
