设计方向的目标是"该品类中最优秀的团队会这样做，并且呈现出这个产品自身的样貌"；仅仅"与模型的默认输出不同"是不够的。高级感来自一整套设计语言的完整性与细节，而非题材的稀缺性。

设计方向中的题材、材质、场景、字体和配色，每一次都应从当前产品的内容、受众与使用场合中推导得出；当所设想的方案与常见的"网红风格"趋同时，必须能够阐明其源于该产品的理由，否则应重新选择。

## 辨识品类与拆解标杆

动手之前应先明确这是什么品类的产品，进而考察该品类中表现最优秀的产品是如何实现的。本步骤确立基准线：用户已经习惯的结构，以及一线产品所达到的完成度。后续的调性确立与生成引擎，都是在这块基准之上寻找这个产品自身的特质。

按三个步骤执行，每一步都应书面记录：

1. **明确品类与标杆。** 说明这是什么品类的产品，例如"语言学习应用"、"组件库官网"、"项目管理工具"、"作品画廊"，并指出该品类中风格最鲜明的两三家。应选取风格最鲜明者，而非知名度最高者。
2. **取得真实画面，再拆解其中一家。** 使用宿主的浏览器或搜索工具，取得这两三家标杆产品首屏及一个关键控件的真实画面，保存至任务目录，对照图像拆解，不凭记忆书写：记忆中的产品往往是它数年之前的形态。若某一家的页面无法打开或返回 404，更换地址再尝试一次，仍不成功则更换另一家；取得两家的真实画面即已足够，无法打开的页面不计入参考。拆解为 6–10 项可观察的要素，每项书写两点内容：它是什么样，以及它为何这样设计。按以下几个层面拆解：控件的形状与交互手感、字体、颜色、图标与插画、状态与反馈、动效、文案语气、首屏承载的内容。拆解应达到可以据以实施的程度：写明形状、尺寸关系、状态如何变化，以及它所服务的使用场合。若拆解结果只有"干净、留白、一种强调色"，说明拆解不到位，应更换一家重新拆解。确实无法取得画面时，在方向卡"标杆与取舍"一节开头写明"未查看图像，依据记忆"，并将字体、色彩、主视觉三栏标注为待验证：这三栏最容易凭记忆写成模型的默认样式。
3. **决定保留什么、更换什么。** 用本产品的受众、内容和使用场合逐条对照：理由同样成立的予以保留，理由不成立的予以更换，更换部分由后续的生成引擎给出替代方案。结果写入方向卡的"标杆与取舍"。

拆解过程中应区分三类对象：

- **基线**：用户已经期待的结构，例如画廊中作品先行展示、筛选器位于顶部，商店中购物车位于右上角。应当沿用，使用户无需重新学习。
- **套路**：该品类人人采用的默认版式。一轮方向中至少应有一个方案打破它，参见"差异化检验"。
- **撞脸**：字体、配色、主视觉和图标均与某个标杆雷同，仅仅更换了名称。任何方向均不允许出现这种情况。

## 先确定调性再追求差异

从产品的题材、受众、品牌语气和使用场合推导调性。使用五个刻度描述，每个刻度都应写明依据：

| 刻度 | 两端 | 在画面上观察什么 |
| --- | --- | --- |
| 能量 | 安静 ↔ 喧闹 | 饱和度、对比度、元素之间是否发生碰撞 |
| 完成度 | 粗粝 ↔ 精致 | 边缘处理、颗粒与噪点、对齐是否严格 |
| 密度 | 疏 ↔ 密 | 留白尺度、叠层、网格纪律 |
| 分量 | 轻 ↔ 重 | 字重、色块面积、阴影硬度 |
| 严肃度 | 活泼 ↔ 庄重 | 圆角、插画语言、动效幅度 |

取值应写成"这个产品是什么 → 五个刻度各取哪一端"，依据来自它的受众、内容和使用场合。刻度两端的任何组合都可以完全成立，真正失败的是没有依据的默认取值：

- 证据指向喧闹粗粝，交付的却是米色卡片、柔和阴影和大面积留白。这是最常见的失败形态，设计被磨回了模型默认的"安静高级"。
- 相反地，为了显得有趣，给一个本应安静的产品强行加入颗粒、撕纸边和粗边框。

当证据已经锁定调性时，所有候选都应保持在同一调性之内，在构图、色彩身份和主视觉上拉开差异。不应为了"平衡"而加入一个安静极简的保底方案。只有当证据确实模糊时，才让候选分布于不同调性之上。

### 模糊表述必须转译

"高级、精致、克制、史诗、有文学感、简洁"不能作为设计理由。当用户或设计者本人使用这类词汇时，应先转译为可观察的设计决策：

| 模糊表述 | 转译为 |
| --- | --- |
| 高级 | 先明确是哪一种高级，再决定字体的对比方式、分隔的方式、间距的尺度与色相的数量。仅说"高级"等于没有作出任何决策 |
| 精致 | 公差：字距如何调整、对齐到几像素的网格、阴影最多几级、色相最多几种 |
| 克制 | 饱和度预算，例如强调色不超过画面的 10%；动效幅度上限；色相数量上限 |
| 史诗 | 尺度：展示字体多大、主图占据多少面积、明暗对比多强 |
| 文学感 | 字族的性格、行长、行高和配色，各取什么值 |
| 粗糙 | 采用哪些手段，各用到什么程度，例如错位多少像素、旋转多少度 |
| 简洁 | 密度档位，以及删掉什么、为何删。简洁是结果，不是指令 |

无法转译为可观察决策的词汇，应从设计理由中删除。

动效与交互层面的模糊表述同样必须转译为具体模式：

| 动效模糊表述 | 转译为 |
| --- | --- |
| 滚动的时候动起来 | 先区分是滑动触发还是滑动驱动，见 [滚动叙事](scroll-narrative.md) 的"滚动交互的两种模式"；未明确时按单向一次性处理 |
| 切换页面丝滑一些 | 选定转场模式：遮罩式、交叠式还是共享元素，取舍与时长见 [动效](motion.md) 的"整页转场的稳定性取舍" |
| 背景有立体感 | **分层视差**：明确前后景的速度差以及哪些层不做视差，按 [滚动叙事](scroll-narrative.md) 的"视差与一镜到底" |
| 首屏要有冲击力 | 明确首屏单一主角（大字排版、一件实物、核心 3D 或视频），不堆砌次要修饰；进场时长见 [动效](motion.md) 的"时长和幅度" |

## 使用生成引擎确立方向

每个方向都应从一个具体的引擎出发，而不是从形容词出发；不同方向最好使用不同的引擎。引擎的内容来自关于这个产品的证据：受众、内容、使用场合和品牌已有的资产。

- **材质 × 环境**：将一种材质置于一个具体的环境之中。由它推导光照、深度、边缘的处理方式以及动效的阻尼。
- **一个具体场景**：一个具备时间、地点和光线的场景。由场景中的光线、声音、材料和节奏推出质感与动效速度。适合情绪型工具。
- **角色原型**：为产品赋予一个具体的性格，让性格决定字体和动作。
- **一场设计运动或文化语法**：选取与产品的题材、受众或地域存在真实联系的设计运动或视觉传统，借用它的语法，而非粘贴它的图案。
- **其他领域的整套表现形式**：借用另一个领域的媒介或器物的表达方式。只借用它最具辨识度的若干个手法，页面本身仍是原来的体裁；不要把那个媒介的部件逐一搬来，那会变成道具堆砌。
- **有意打破常规**：激进的非对称版式、不和谐的配色与字体、令人不安的留白，但整体仍然美观、功能完整。

引擎决定结构、手感、质感和动效；颜色按下一节单独确定。

## 确定配色

产品自身的品牌资产、实物和内容画面是颜色的首要来源；主视觉就是产品实物时，主色可以直接从实物中提取。没有现成主色时，不应直接采用生成引擎中那种材质或场景的固有色作为主色——隐喻一旦落到黄铜、木纹或暗房，不同的产品最终就会撞进同一组颜色。按三步确定：

1. 先写两行，供几个方向共用：该品类最常用的默认配色是什么，写出底色和强调色；已拆解的标杆各占据了哪个色相与明暗区间。
2. 每个方向确定一套不同的色相与明暗，或者明确使用黑白，用一句话说明它来自这个产品的什么：内容、受众或品牌资产。应避开刚刚拆解过的标杆配色；至少一个方向要跳出该品类的默认配色。
3. 写出至少三层：底色、主强调色，以及由它们派生的选中底色、描边和禁用态。

黑白灰加一种强调色，甚至完全不使用彩色，同样是完整的色彩身份，此时颜色交给内容：产品截图、用户的照片、一幅画作。几个方向之间不应按明暗区分：头号失败是"一个亮、一个暗、一个暖"，每个方向都要有自己的色相家族或材质感，明暗只是结果。

## 确定首屏与工作区骨架

在撰写文案之前先确定骨架，让文案去适应骨架。首先回答一个问题：**用户来到首屏是看什么、做什么？**

- **来听一句话、看一张画、接受说服的页面**（落地页、品牌页、产品发布页、展览页）：
  从八种首屏骨架中选择，跳出左右分栏的默认模板。详见 [说服型页面首屏骨架](direction-persuasion.md)。
- **来浏览内容、挑选物件或处理对象的页面**（画廊、商店、信息流、文档、作品集、工具和后台）：
  首屏即第一排内容本身或工作区。导航、标题和筛选合计不超过一两行，第一排内容应完整出现在首屏。不放置首屏口号，也不放置解释该页面用途的段落。按用户最常执行的动作安排内容，例如浏览就让内容铺满，处理就让当前对象与动作相邻；主区保持清爽透气，完整详情与日志按需在选中对象后滑出或展开，不用多层小卡片和满屏彩色标签把桌面塞满。
- **两类兼有时**（例如商店首页顶部有活动横幅）：以用户最常来做的事为准，横幅可以保留，但不能把第一排内容推出首屏。

## 方向卡

每个方向撰写一张方向卡，每项都填写具体决策，不填写形容词。产出三个首屏的那一轮，调性和标杆与取舍几项由几个方向共用一份（候选分布于不同调性时，调性各填各的），每个方向只填北极星、生成引擎、首屏骨架、字体、色彩、主视觉、图标和控件语法；其余各栏在方向选定之后、制作完整页面之前补齐。派生版式时，每个版式变体只重写首屏骨架、页面结构和主视觉三栏：

| 字段 | 应达到的详细程度 |
| --- | --- |
| 北极星 | 一句能够指导取舍的意图：给人第一印象是什么，整页围绕什么展开 |
| 调性 | 五个刻度的取值及依据 |
| 标杆与取舍 | 品类是什么，拆解的是哪一家，对照哪几张真实画面拆解（写明存放路径；未查看图像则写"未查看图像，依据记忆"）；沿用了哪几条、更换了哪几条，各自理由 |
| 生成引擎 | 使用了哪一种，具体内容是什么，源于这个产品的什么证据 |
| 首屏骨架 | 先写用户来首屏看什么。内容页写首屏能看到几个对象、页头占据几行；说服型页面写从骨架表中选定的哪一种，附三至五个方框的首屏线框：每块是什么、占据多大面积、阅读从哪里开始 |
| 页面结构 | 首屏以下如何组织，例如单列沉浸滚动，或导航、内容、详情三栏 |
| 各区块的形式 | 首屏以下每个主要区块（产品实样、功能、价格、隐私、结尾等）在该方向中呈现为什么形态。形式从生成引擎推导，而不是同一模块更换颜色 |
| 字体 | 具体字族、字重和尺度关系：展示、正文、数字各使用什么，相差多大 |
| 色彩 | 按"确定配色"撰写：十六进制色值及用途，至少三层，再加一句它来自这个产品的什么 |
| 主视觉 | 由哪张图或哪个图形承担情绪与识别功能，来源于复用、生成还是排版本身 |
| 图标 | 使用哪一套、描边粗细与端点为何，或者不使用图标、改用字符和编号 |
| 控件语法 | 按钮、输入、选中、标签、状态和动效共用的一套形状和手感，用一句话写明，例如圆角多大、描边多粗、按下时如何变化 |
| 动效 | 手感用"一个拟声词加一个实物的动作"来描述，实物从这个产品的领域内寻找；三处基本动效各自如何运动、如何彼此呼应；落地页类页面再写滚动分镜（区块出场、选择了哪种滑动驱动的叙事），见 [滚动叙事](scroll-narrative.md)。参见 [动效](motion.md) |
| 结构性突破 | 改变首屏结构的那一处偏离常规，以及它如何放大北极星。手写批注、质感按钮、划线这类局部细节不在此列 |
| 记忆点 | 集中发力的一两处：在哪个时刻或位置，使用什么材质、动作或画法，见"形成记忆点" |
| 放弃什么 | 该方向主动舍弃的常见做法 |

北极星、字体、色板和特征直接写入对比页 manifest，与画面一同展示。

## 差异化检验

方向卡填写完成、制作首屏之前，逐条检验。基于选定方向派生版式，或用户已经给出品牌规范时，字体和配色是共用的，以下关于字体和色彩的条目不适用，骨架、主视觉和页面结构仍须各不相同：

- **比较线框，不比较描述**：将各方向的首屏线框并列放置比较。方向的描述可以各不相同，线框却可能都是"左边大标题，右边小块"。线框相似即为同一骨架，应重新选择骨架。
- **四项至多一项相同**：首屏骨架、字体、色彩、主视觉四项中，任意两个方向至多一项相同；否则即为同一方向的变体，应更换一个生成引擎重写其中之一。
- **不按明暗区分方向**：每个方向都有自己的色相家族或黑白，见"确定配色"。
- **结构也须不同**：填写了"页面结构"的几个候选（版式变体，或均要制作成整页的方向），页面组织不能完全相同、仅更换颜色和质感。候选只需共享核心内容和主要任务。
- **至少一个走向极端**：在证据允许的调性范围内，至少一个方向在构图、色彩和主视觉上都作出明确选择，不作折中；折中的方向最多一个。
- **至少一个打破品类套路**：在同一调性内，至少一个方向不使用该品类的默认版式。打破套路不等于抛弃基线。常见套路如下：
  - 后台：左侧栏、顶栏加卡片网格。
  - 电商：大横幅、商品网格加页脚。
  - 社交：底部标签栏、信息流加悬浮按钮。
  - 落地页：主视觉、特性、用户评价，最后一个行动按钮。
  - 聊天：左侧联系人，右侧消息。
  - AI 与开发者工具：黑色背景、紫蓝发光弥散圆晕、浮空粒子与千篇一律的胶囊按钮。
- **不撞脸**：将每个方向与它拆解过的标杆并列查看，撞脸即重做，定义见"辨识品类与拆解标杆"。沿用基线不算撞脸。
- **盲测**：遮住名称和说明，只看画面，仍能说出每个方向带给人的不同感受。

首屏完成后再比较一次实际画面：在对比页并列查看首屏，眯起眼睛只看明暗块面。若块面分布相似，例如都是左边一大块、右边一小块，即使字体和颜色都不同，也要回到骨架表重做，不靠更换装饰补救。

## 设计北极星与元素呼应

北极星确定后，应将其落实为全页一致的关系：每一屏谁是主角，次要信息如何退后，哪种排版或图形在全页重复出现以形成节奏，哪一处使用反差突出主操作。

结构性突破要改动的是结构，例如首屏的骨架、比例或阅读顺序，而不是额外增加一个装饰；它要么强化主题，要么把人引向关键动作。精修时，不要把有辨识度的选择磨平。新增的元素若不能强化同一个意图，就不添加。

## 形成记忆点

每个方向选取一两处集中发力，其余保持安静。记忆点通常是一个组件的一次动作：结果、材质、光影、手感和节奏都做到位。

寻找位置：

- **用户会执行的动作。** 点按、拖动、切换、提交，比滚动更容易成为记忆点。
- **关键时刻。** 付款成功、第一次完成任务、升级、删除、上传、等待结果。这些时刻情绪最强，一个小动画的回报最高。
- **边缘页面。** 404、空状态、加载、页脚。无人寄予期待，风险又低，最容易出彩。
- **AI 正在工作的过程。** 让过程可见，进行中和完成的区别直接落在画面和内容变化上，不只依靠转圈动画。

思考方法：

- **让结果当场发生。** 状态切换不只更换一个图标，而是让受影响的东西当场变化。用户看到的是结果，不是控件在表演。
- **把数字画成可见的量。** 百分比、时长、余额，先判断能否画成面积、长度或个数。数字只是标签，量才是画面。
- **借用该领域中的真实事物交付结果。** 先看用户做这件事时手上拿着什么、眼里看着什么，例如音轨、画布图层、包裹、账单，借用它的样子和动作把状态呈现出来。票据、打印机、卡带、老游戏机这类复古道具已经泛滥，与产品无关时不要套用。
- **赋予控件物理属性与性格。** 拖动有弹性和重量，按下有光影变化，拉过头会不情愿地弹回。
- **画法要能说出来源。** 点阵、字符画、像素、粒子、写实材质这类画法，只有在能够说出它源自产品所做的事情时才选择。说不出来源就不选；一旦选定，就从主视觉一路用到加载、图标和空状态。

## 将参考转化为设计决策

先说明这份参考的用途：借用它的视觉关系，把它作为质量底线，还是依照它精准还原。查看图像之后再描述它的形态。借鉴时取的是关系，例如"标题最重，图像负责情绪，辅助信息压得很淡"，再用当前的内容重新组织；不照搬参考中的业务模块、标识和文案。借用的隐喻要落实为具体的界面决策，不做成一层妨碍操作的仿真外壳。

参考中没有的东西同样是决策。参考的首屏没有标题区和说明段，就不要替它补上；参考没有使用的装饰，也不要加回去。

## 样本、选择与品味

方向只做首屏，不在一开始制作多套完整产品；轮次和数量见 SKILL.md 阶段一。

首屏选取能够暴露方向优缺点的那一页：包含复杂表单的产品不能只做封面。

介绍产品的页面，必须让用户看到产品真正交付的东西：一张生成好的报表、一份导出的合同、一段处理后的真实数据，而不是只用文字承诺"能够做什么"。这个实样往往比功能列表更有说服力，也最容易成为首屏以下某一段的主角。

推荐理由应从任务适配、辨识度、内容承载、可读性和实现代价中比较得出。请用户补充品味时，询问希望获得什么感受、不希望出现什么及其原因、哪些地方需要保留。用户只说"再高级一点"时，用上文的转译表追问，或提供两张小样让用户比较。

将选定方向与品味写入设计说明，作为后续判断的基准。评审提出新风格时，先判断它是否解决原有目标；只有当前方向确实不适配，或用户改变目标时，才重新探索。
